# Спецификация визуальной переработки инфраструктурной карты

Статус: аналитическое решение зафиксировано, в атлас не внедрено.

Дата: 2026-07-30.

## 1. Зафиксированные условия

- Изохроны 20 и 60 минут рассчитаны именно от больниц.
- Красная гамма изохрон отделяет доступность больниц от остальных слоёв и
  сохраняется как самостоятельная семантическая семья.
- Существующие пиктограммы медицинских учреждений считаются временными и будут
  полностью заменены.
- Цвета учреждений должны быть категориальными, а не вариациями одной
  сине-зелёной гаммы.
- Кластеры медицинских учреждений должны быть кольцевыми диаграммами:
  размер показывает общее число объектов, цветные сектора — состав по типам.
- До отдельного согласования макета изменения в рабочий интерфейс не вносятся.

## 2. Почему текущая кластеризация недостаточна

Сейчас кластер — одноцветный круг, цвет которого меняется только от количества
точек. Он отвечает на вопрос «сколько», но не показывает «какие учреждения».

Состав исходных данных:

| Тип | Количество | Доля |
|---|---:|---:|
| ФАП | 304 | 72,9% |
| Поликлиники | 39 | 9,4% |
| Больницы | 32 | 7,7% |
| Амбулатории | 19 | 4,6% |
| Консультации | 7 | 1,7% |
| Реабилитация | 7 | 1,7% |
| Родильные дома | 6 | 1,4% |
| Здравпункты | 3 | 0,7% |

На мелком масштабе ФАП закономерно займут большую часть кольца. Поэтому нельзя
искусственно выравнивать сектора: это исказит данные. Небольшие доли должны
сохранять реальный угол, отделяться тонким нейтральным разделителем и
расшифровываться во всплывающей карточке.

## 3. Кластер в виде «бублика»

### Визуальная модель

- Внешнее кольцо делится на сектора по восьми типам учреждений.
- Порядок цветов всегда фиксированный, а не сортируется по величине.
- Нулевые категории не создают сектор.
- Центр кольца нейтральный: светлый либо тёмный в зависимости от результатов
  контрастного теста.
- В центре показывается общее количество объектов.
- Диаметр зависит только от общего количества:
  - 2–9 объектов: 34–36 px;
  - 10–29: 42–44 px;
  - 30–74: 50–52 px;
  - 75 и более: 58–62 px.
- Толщина кольца растёт от 6 до 10 px вместе с диаметром.
- Между секторами используется разделитель 1–1,5 px нейтрального цвета.
- Внешний контур — полупрозрачный графитовый, без массивного белого ореола.

### Интерактивность

- Наведение показывает: общее число и три ведущих типа.
- Нажатие раскрывает полный состав по всем ненулевым типам и долям.
- Повторное действие либо отдельная кнопка приближает карту до распада кластера.
- При выключении категории источник кластеризации пересчитывается, поэтому
  кольцо и центральное количество отражают только видимые типы.

### Технический подход

В GeoJSON-источник добавляются `clusterProperties` — восемь счётчиков:

```js
clusterProperties: {
  hospital_count: ["+", ["case", ["==", ["get", "facility_code"], "hospital"], 1, 0]],
  polyclinic_count: ["+", ["case", ["==", ["get", "facility_code"], "polyclinic"], 1, 0]],
  fap_count: ["+", ["case", ["==", ["get", "facility_code"], "fap"], 1, 0]]
  // и остальные категории
}
```

Рекомендуемый рендер — динамический Canvas/SVG-спрайт внутри `symbol`-слоя
MapLibre:

1. Ключ изображения строится из восьми счётчиков кластера.
2. Кольцо генерируется только один раз для каждой уникальной комбинации.
3. Изображения кэшируются и дальше рисуются WebGL-картой.
4. Число в центре остаётся отдельным текстовым слоем.

Так карта сохраняет единый WebGL-конвейер и не создаёт множество постоянно
перемещаемых HTML-элементов. Для 417 исходных точек запас производительности
достаточный.

Альтернатива — HTML-маркеры с SVG-кольцами по официальному примеру MapLibre.
Она проще в разработке, но создаёт отдельный DOM-элемент на каждый видимый
кластер и хуже соответствует приоритету производительности.

## 4. Цветовая архитектура

Цвет назначается не всей карте целиком, а семантическим группам.

### Слои контекста

- Подложка и дороги: нейтральные светло-серые.
- Муниципальные границы: холодный графит или серо-синий, минимальная заливка.
- Населённые пункты: нейтральный серо-графитовый знак; размер остаётся
  кодировкой населения.
- Изохроны от больниц: отдельная красная семья:
  - 20 минут — более насыщенная заливка;
  - 60 минут — тот же цвет с меньшей непрозрачностью;
  - границы можно оставить без линии либо использовать очень тонкую линию.
- Медицинские учреждения: контрастная категориальная палитра.

### Кандидат A — контрастная категориальная палитра

Рекомендуемый вариант для первого макета:

| Тип | Цвет-кандидат |
|---|---|
| Больницы | `#2563EB` |
| Поликлиники | `#059669` |
| ФАП | `#D97706` |
| Амбулатории | `#0891B2` |
| Родильные дома | `#BE185D` |
| Консультации | `#EA580C` |
| Реабилитация | `#7C3AED` |
| Здравпункты | `#64748B` |

Красный не используется для типов учреждений, поскольку он зарезервирован за
изохронами доступности больниц.

### Кандидат B — функциональные семьи

- стационарная помощь — синие;
- амбулаторная помощь — зелёные;
- первичное сельское звено — оранжевые;
- специализированные учреждения — пурпурные;
- здравпункты — нейтральные.

Этот вариант лучше передаёт медицинскую иерархию, но внутри одной семьи типы
будут различаться хуже. Для текущей задачи он не рекомендуется как основной.

## 5. Новая система пиктограмм

### Общие правила

- Один `viewBox 24×24`.
- Единая толщина линии 1,8–2 px.
- Скруглённые окончания и соединения.
- Без мелких декоративных деталей.
- Белый или очень светлый фон знака, цветная обводка и цветной глиф.
- Один и тот же цвет используется в панели, одиночной точке, секторе кластера
  и всплывающей карточке.
- Значок должен распознаваться не только по цвету.

### Предлагаемые метафоры

| Тип | Основной образ |
|---|---|
| Больница | корпус/койка и медицинский крест |
| Поликлиника | амбулаторное здание или карточка пациента |
| ФАП | небольшой сельский дом с крестом |
| Амбулатория | медицинская сумка или стетоскоп |
| Родильный дом | взрослый и ребёнок внутри крупного символа сердца |
| Консультация | диалог и небольшой медицинский крест |
| Реабилитация | фигура человека в движении |
| Здравпункт | компактный щит или аптечка с крестом |

## Реализованная логика чтения кластеров

1. На обзорном масштабе число в центре показывает количество объектов.
2. Толщина кольца увеличивается вместе с количеством объектов.
3. Цветные секторы показывают реальные доли типов без искусственного
   выравнивания.
4. Небольшая точка внутри кольца окрашена в цвет доминирующего типа.
5. При наведении показываются точные значения всех ненулевых типов, количество
   разных типов и ведущая категория.
6. При клике карта приближается до масштаба распада выбранного кластера.

Режим «функциональная мощность» не рассчитывается до утверждения весов и
классификации уровней учреждений. Для него потребуется отличать участковые,
районные, межрайонные и областные больницы. После подготовки признака мощности
он добавляется как отдельный переключаемый режим и не заменяет обычное
количество объектов.

Не рекомендуется снова использовать одинаковый цветной квадрат для всех
категорий: при уменьшении карты различия глифов исчезают, и знаки превращаются
в визуально одинаковые пятна.

## 6. Порядок будущего внедрения

1. Нарисовать отдельный лист из восьми пиктограмм в трёх размерах:
   16, 24 и 32 px.
2. Сделать два изолированных макета палитры без изменения атласа.
3. Согласовать палитру и метафоры пиктограмм.
4. Добавить восемь `clusterProperties`.
5. Реализовать кольцевой кластер и карточку состава.
6. Подключить новые одиночные знаки.
7. Проверить фильтрацию категорий, распад кластеров и масштабирование.
8. Проверить 1300×700, 1600×950 и 2560×1440.

## 7. Критерии готовности

- Изохроны не смешиваются визуально с учреждениями.
- Каждый тип учреждения различим без чтения подписи и без опоры только на цвет.
- Цвет сектора кластера совпадает с цветом соответствующего типа.
- Сумма секторов равна числу в центре.
- Выключение типа сразу меняет и сектора, и центральное число.
- Кольца не закрывают подписи и населённые пункты на обзорном масштабе.
- Масштабирование и наведение не создают заметных задержек.
- Точная структура кластера доступна во всплывающей карточке.
