# ADR-0002: Проверяемая публикация GitHub Pages из `dist`

## Статус

Принято, этап 5.3.

## Контекст

Атлас остаётся статическим сайтом, но его production-модуль уже собирается Vite из React + TypeScript. Публикация корня репозитория смешивала исходники, тесты и готовые файлы, не обеспечивала автоматическую проверку контрольных сумм и затрудняла откат.

Ограничения: GitHub Pages, отсутствие серверной части, крупные локальные наборы данных, обязательное сохранение legacy-fallback и минимальная стоимость сопровождения.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы | Сложность |
|---|---|---|---:|
| Публикация корня `main` | Никакой новой сборки | В сайт попадают служебные файлы; нет барьера качества; слабый контроль кэша | Низкая |
| Отдельная ветка `gh-pages` | Production-файлы отделены | Генерируемые коммиты, дополнительная ветка и риск рассинхронизации | Средняя |
| GitHub Actions → проверенный `dist` | Чистый артефакт, тесты до публикации, точные SHA-256, история артефактов | Workflow и browser smoke требуют нескольких минут | Средняя |
| Полный переход на framework-router/SSR | Единая современная сборка | Не нужен для статического атласа и повышает стоимость миграции | Высокая |

## Решение

Выбран GitHub Actions с публикацией только каталога `dist`.

1. Vite собирает React-islands.
2. Белый список копирует `index.html`, `manifest.json`, `assets/`, `data/` и `tables/`.
3. Локальные зависимости получают версии из первых 12 знаков SHA-256.
4. `build-manifest.json` фиксирует путь, размер и полный SHA-256 каждого production-файла.
5. Перед публикацией выполняются валидация данных, unit-тесты, TypeScript, воспроизводимость упаковки и browser smoke основного и fallback-путей.
6. Отдельный неизменяемый артефакт хранится 30 дней. Ручной запуск workflow принимает `deploy_ref`, поэтому предыдущий проверенный коммит можно собрать и опубликовать повторно.
7. После `deploy-pages` публичная версия повторно скачивается и сверяется с собственным манифестом.

## Компромиссы

- Публикация медленнее прямой отдачи ветки, зато повреждённая сборка не доходит до Pages.
- На этом этапе React-бандл продолжает создаваться в `assets/react`; отдельная перестройка структуры Vite отложена, чтобы не ломать локальный legacy-режим.
- Артефакт отката хранится ограниченное время, но любой более старый коммит этапа 5.3+ можно повторно собрать через `deploy_ref`.

## Последствия

- Production-содержимое отделено от исходников.
- Кэш браузера обновляется по содержимому, а не по вручную назначенной дате.
- Сборка и опубликованный сайт имеют проверяемую цепочку контрольных сумм.
- Для первого запуска владелец репозитория должен выбрать **Settings → Pages → Source: GitHub Actions**.

## Условие пересмотра

Решение следует пересмотреть при переходе на полноценный SPA-router, появлении серверной части или превышении лимитов GitHub Pages/Actions.
