# Порядок гибридной миграции React + TypeScript

## Цель

Перевести атлас на типизированную компонентную архитектуру без одновременной переписи работающих карт и SVG-визуализаций. GitHub Pages остаётся статическим хостингом; Node.js используется для сборки, тестов и подготовки данных.

## Этап 0. Контрольная точка

- создать ZIP рабочей версии и полный Git bundle;
- сохранить исходный commit и контрольные SHA-256;
- зафиксировать показатели производительности и объёмы данных.

## Этап 1. Сборочная среда и мост совместимости

- Vite, React и TypeScript подключаются отдельным модулем;
- существующий HTML остаётся рабочим без Node.js в браузере;
- классический JS-мост публикует React только типизированный снимок состояния и сводку данных;
- диагностический React-компонент скрыт в штатном режиме и доступен через `?reactDebug=1`;
- unit- и browser-тесты контролируют количество записей, справочники и синхронизацию фильтров.

## Этап 2. Общая оболочка и состояние

- перенести верхнюю строку состояния и глобальные фильтры в React;
- создать единое типизированное хранилище фильтров;
- legacy-визуализации получают состояние через адаптер;
- сохранить фильтры при переключении вкладок.

## Этап 3. Панели карт

- перенести левую панель и правый аналитический контекст карт в React;
- MapLibre остаётся императивным движком и не пересоздаётся при ререндере React;
- данные карты обновляются через узкий адаптер команд;
- код и данные каждой карты загружаются лениво.

## Этап 4. Аналитические вкладки

- переносить по одной вкладке: treemap, матрица, ранги, пирамида, возраст, точки;
- расчёты вынести в чистые TypeScript-функции;
- SVG остаётся отдельным слоем рендера до появления измеримой причины заменить его;
- для длинных списков применять виртуализацию, для тяжёлых агрегаций — Web Worker.

## Этап 5. Данные и публикация

- вынести 30 232 записи из HTML в версионируемые файлы данных;
- разделить общие геоданные, инфраструктуру, изохроны и дороги;
- добавить контроль схемы и контрольные суммы;
- GitHub Actions собирает `dist/` и публикует его в GitHub Pages.

## Правила совместимости

1. На каждом этапе число записей, классов, блоков, кодов, МО и НП сверяется с контрольной версией.
2. Рабочая карта MapLibre не пересоздаётся при обычном изменении фильтра.
3. React не получает полный массив наблюдений до этапа переноса слоя данных.
4. Любой новый React-компонент должен иметь legacy fallback до завершения соответствующего этапа.
5. Этап считается завершённым только после typecheck, unit-тестов, browser smoke-теста и сравнения производительности.
